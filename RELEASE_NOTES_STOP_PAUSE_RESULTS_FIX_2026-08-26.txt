STOP / PAUSE / RESULTS CORRECTNESS FIX — 2026-08-26
===================================================

Scope: GUI and postprocessing only. Solver mechanics and MVI algorithms are unchanged.

1. STOP after any accepted step
- Accepted STEP_xxxx_STATE.npz is authoritative even if STEP_xxxx.json or FINAL summary was not written yet.
- GUI STOP automatically starts FULL postprocessing when at least one accepted step exists.
- Generic nonconvergence/abnormal termination with accepted states also starts FULL automatically.
- FULL produces the complete final accepted-step result package: graphs, section cuts, 3D, VTK, numeric NPZ/CSV/JSON and full Excel exports.
- STOP terminates the process tree so a child worker cannot keep writing while postprocessing reads the run folder.

2. PAUSE / RESUME
- The whole solver process tree is suspended/resumed.
- On PAUSE the GUI refreshes only already accepted STEP state files; an in-progress step is never added to load-deflection history.
- Resume continues the existing accepted-step sequence without duplicate points.
- Paused wall time is excluded from the GUI running-time counter.

3. Load-deflection correctness
- X axis = absolute deflection; Y axis = physical load.
- The center curve uses |w(center)|; the diagnostic curve uses |w|max.
- If STOP happens between state save and STEP JSON save, load factor is recovered from GENERATED_LOADS.npz / the saved FINAL_CASE load sequence, never from the step number.
- Online labels and load conversion use the immutable load definition and unit system of the active RUN, not editable GUI fields.

4. Result viewer correctness
- Geometry L/R, material E0/nu0 and Birger yield criteria for online/result rendering are read from the saved RUN metadata.
- Editing GUI inputs after Start no longer changes GB/G0, plastic-zone display, shell geometry or units for an already running/saved calculation.
