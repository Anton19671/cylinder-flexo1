CYLINDER SOLVER — ONLINE / EXTENDED RESULTS / INDEPENDENT EXCEL
Release extension 2026-08-17

Scope
-----
This extension changes GUI/progress/output/postprocessing only. Governing equations,
constitutive mechanics, V3 analytic tangent, Birger outer algorithm and MVI equations
are not changed.

1. Automatic independent run folder
-----------------------------------
The folder selected in GUI is now a RESULTS ROOT. Every Start creates a new child
folder whose name contains timestamp, optional user run label, theory/CUF model,
method/rank, physical mode, L/R/h, E/nu, BC token, load token and grid. Repeated
variants cannot overwrite each other: __02, __03, ... is appended when needed.

Each calculation folder contains immutable/replay input files:
  INPUT/FINAL_CASE.json
  INPUT/RUN_PARAMETERS.json
  INPUT/GUI_PRESET.json
  INPUT/FILES/... snapshots of external NPZ/CSV inputs when applicable
  RUN_INFO.json
  PARAMETERS.txt

GUI fields stay filled after a run. To reproduce an older run, open its
INPUT/GUI_PRESET.json from the normal "Open parameters" command.

2. One independent Excel per calculation
----------------------------------------
Every ordinary calculation writes its own RESULTS_<run-name>.xlsx inside that
calculation folder. It has no links to other workbooks and is intended to be usable
by a third party independently from the solver.

Main sheets are created when data exist:
  README
  Parameters
  Step_Summary
  Load_Deflection (includes explicit 0,0 and a chart)
  Online_History
  Newton_History
  MVI_History
  Birger_History
  Control_Points
  Surface_Fields
  Thickness_Fields
  CUF_Coefficients
  CUF_Standard_Z
  Resultants

Long field tables are automatically split across multiple sheets before reaching
Excel row limits. Raw NPZ/JSON remain the machine-precision authoritative data.

For an MVI-1...8 series, every MVI_N/OUT folder gets its own independent
RESULTS_MVI_N.xlsx. A global series CSV/JSON and rank convergence graph are kept in
the parent series folder, but they do not replace the rank-specific Excel files.

3. Online calculation tab
-------------------------
The dedicated Online tab reads the solver's atomic LIVE_PROGRESS.json and append-only
LIVE_PROGRESS.jsonl. It displays scalar progress frequently while throttling heavy
visual rendering.

Common online status:
  elapsed time, current step/total steps, load factor, calculation stage,
  current |w|max and coordinates.

FDM/Newton:
  Newton iteration, residual_inf, residual_relative, convergence residual,
  increment, interior/boundary/load-front residual diagnostics.

MVI:
  rank, Y/X half-step, half-step iterations, projected residual Rproj,
  X<->Y cycle, field increment/change, |w|max.

Birger:
  outer iteration, eta_G, eta_sigma, GB/G0 min/max, max epsilon_i,
  max |J-1|; completed-step plastic/nonlinear fractions are available from saved
  derived state.

Online also includes:
  table of accepted/completed load steps;
  load-deflection curve starting from (0,0);
  selectable accepted-step 3D deformed shell;
  selected online field/plasticity map;
  convergence history plots.

Heavy 3D/maps are based on accepted state data rather than being redrawn for every
inner algebraic operation.

4. Stop behavior
----------------
Stop terminates only the active calculation subprocess. Already accepted steps remain
on disk and in the online table. After Stop, if at least one accepted step exists,
postprocessing is started for those accepted steps so DERIVED files, plots and the
independent Excel are still produced. The incomplete step is not promoted to an
accepted result.

5. Extended CUF/Carrera result state per accepted step
------------------------------------------------------
NUMERIC/STEP_xxxx_DERIVED.npz stores, when applicable:
  CUF coefficients q = {u_tau,v_tau,w_tau};
  physical u,v,w at actual thickness quadrature points;
  physical u,v,w at z=-h/2,-h/4,0,h/4,h/2;
  6 strain components and 6 stress components;
  epsilon_i, sigma_i, detF;
  GB and GB/G0 for Birger;
  generalized resultants;
  actual z coordinates and quadrature weights;
  applied radial surface load for built-in load types;
  physical deformed midsurface XYZ.

The Results GUI can select step, field, x/s point, tau and z and can plot:
  surface map;
  3D accepted shell;
  through-thickness profile;
  x-z cut;
  s-z/theta-z cut.

6. Plasticity / Birger output
-----------------------------
Material variables are evaluated and stored on the actual through-thickness
integration levels, not invented geometric surface points.

Always for Birger:
  GB/G0 field;
  Birger nonlinear/degraded mask GB/G0 < 1-1e-10;
  weighted nonlinear thickness fraction;
  weighted nonlinear volume fraction;
  bottom/middle/top integration-layer maps;
  x-z and theta-z cuts;
  through-thickness GB/G0, epsilon_i and sigma_i profiles.

When the user explicitly provides yield_stress or yield_strain for visualization:
  plastic_mask(x,s,z);
  weighted plastic_thickness_fraction(x,s)=hp/h;
  weighted plastic_volume_fraction Vp/V;
  bottom/middle/top plastic layer maps;
  plastic x-z and theta-z cuts;
  first detected plastic point coordinates;
  plastic area fractions at bottom/middle/top integration levels.

Thickness and volume fractions use actual quadrature weights and the cylindrical
factor H=1+z/R.

7. Postprocessing responsiveness
--------------------------------
Normal postprocessing runs in a separate subprocess so the GUI remains responsive.
MVI-series postprocessing is also asynchronous. Excel generation is part of the
postprocessing stage.

8. Dependency
-------------
XlsxWriter is added to requirements.txt. START_PROGRAM.cmd and
INSTALL_REQUIREMENTS.cmd check/install NumPy, Matplotlib and XlsxWriter.
