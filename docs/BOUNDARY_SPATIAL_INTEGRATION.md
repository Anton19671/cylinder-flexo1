# Граничные условия: пространственная сборка

`numerics/cylinder_boundary_spatial.py` соединяет единый объёмный функционал
с механической работой на торцах, пружинами, высшими следами, электродами
и поверхностным зарядом. Для статики и динамики добавлен отдельный проверочный
маршрут CASE, описанный ниже. Обычный производственный маршрут MICRO
по-прежнему отделён от него.

Поддерживаются KL, FSDT, Reddy и CUF TE1–TE4. Выключенная электрическая
часть полностью исключается из вектора неизвестных. Все величины задаются
в СИ; порядок полей — `(компонента, x, s)`, электрические коэффициенты
следуют за механическими. Это отличается от `(компонента, s, x)` старых
производственных маршрутов, поэтому прямой передачи массивов между ними нет.

Условия задаются линейными строками `C u = d(t)`. Аффинное представление
`u = u0 + B z` обеспечивает `C u0 = d(t)` и `C B = 0`. Пространственные
уравнения получаются как `B.T R = 0`, касательная — `B.T K B`.
Полный остаток сохраняет реакции закреплений и электродов, поэтому его
нельзя требовать равным нулю на закреплённых степенях свободы.

МКР (`method="FDM"`) использует все узловые направления. Для полушага МВИ
передаётся матрица направлений замороженного семейства X или Y, построенная
через `separated_profile_directions(X, Y, "X"/"Y")`; ранги — 1–8.
Ограничения накладываются внутри этого пространства. Если заданные следы
недостижимы, сборка возвращает ошибку, без перехода к полносеточному решению.
Для неоднородных условий нужно отдельно хранить аффинное поднятие и
представлять МВИ допустимую добавку. Малый остаток одного полушага ещё
не подтверждает полное равновесие.

Для изолированной электрической системы проверяется суммарный объёмный
и поверхностный свободный заряд, затем добавляется калибровка среднего
потенциала. При наличии электрода с заданным потенциалом калибровка
не добавляется; электрод может поставлять заряд. Проверка баланса использует
относительную точность и не пропускает дисбаланс из-за малых единиц Кл.

В DYNAMIC на каждом времени заново вычисляются заданные перемещения,
потенциалы и нагрузки. Вектор ускорений и плотность можно передать в ту же
сборку: механическая инерция берётся из соответствующего CUF/director
функционала, электрическая масса не добавляется. Нелинейная инерция KL
остаётся явно неподдерживаемой. Полный проверочный цикл Ньюмарка описан ниже.

Проверки: `tests/test_boundary_spatial.py`, а также существующие тесты
вариационного функционала, граничной работы и CASE. Они проверяют допустимые
следы, энергетические производные, проекцию касательной, реакции, балансы
заряда, временные данные и применение выбора в GUI без ручной синхронизации
JSON. Эти проверки не являются исследованием сходимости оболочечного решения.

Следующий этап — адаптеры порядка полей и масштабов для разреженных
производственных циклов, предварительно нагруженные начальные состояния и
временные существенные ГУ с явными скоростью и ускорением заданного следа.

Плотная сборка ограничена 4096 неизвестными/строками и предназначена для
малых проверочных задач. Она не заменяет разреженную производственную сборку.

## Запускаемый статический МКР

`numerics/cylinder_variational_fdm.py` решает связанные нелинейные узловые
уравнения методом Ньютона. `solver_backend="VARIATIONAL_REFERENCE"` явно
выбирает этот маршрут в `run_final_case` и `validate_final_case`. Пример:

```bash
python RUN_FINAL_CASE.py config/CASE_REFERENCE_CUF_G3D_STATIC.json
```

Числа в примере предназначены для проверки программы, а не для воспроизведения
конкретного материала или эксперимента. Результаты сохраняются в отдельную
папку, заданную `output_dir`. Повторный запуск требует новой пустой папки.

Маршрут принимает STATIC, FDM/MVI, GREEN_LAGRANGE, HOOKE и СИ. Доступны KL,
FSDT, Reddy, CUF TE1–TE4; MACRO либо MICRO G3D с флексоэффектом ВКЛ/ВЫКЛ.
В CASE нужен явный вариационный паспорт ГУ. Электрические ГУ при флексо ВЫКЛ
GUI переключает электрический паспорт на изолированный при ФЛЕКСО ВЫКЛ,
сохраняя предыдущие настройки для обратного переключения.

Нагрузка: равномерное мёртвое радиальное давление на срединной поверхности
(`UNIFORM_RADIAL_FACE`, `MIDDLE`, `DEAD_REFERENCE`, положительное q — наружу)
либо явные обобщённые нагрузки `reference_loads.mechanical` и
`reference_loads.free_charge`. Обобщённые нагрузки сопряжены коэффициентам
полей и не являются произвольным давлением на внешнюю поверхность. Вектор
по компонентам разворачивается равномерно по сетке; также принимаются полные
массивы `(компонента, x, s)`. `load_factors` задаёт статическую серию:
масштабируются эти нагрузки, но не заданные перемещения/потенциалы в ГУ.
Нагрузки на внешнюю/внутреннюю поверхность и следящие силы пока отклоняются.

Касательная вычисляется центральными разностями от той же первой вариации.
Связанная неопределённая система решается напрямую; поиск шага уменьшает
остаток, а не энтальпию электрической седловой системы. Вырожденная касательная
вызывает отказ без регуляризации. Отдельно контролируются условия закреплений,
электроды и полный допустимый остаток; реакции сохраняются отдельно.

Поля нормируются: поступательные/CUF коэффициенты на h, повороты на 1 рад,
потенциал на `potential_scale_v`; энергия — на `E*h*area`. Абсолютный допуск
относится к производной этой безразмерной энергии, относительный — к начальному
допустимому остатку данного шага. Масштабы и оба остатка записываются в отчёт.

Выход: `FINAL_RUN_SUMMARY.json`, исходный `REFERENCE_CASE.json`,
`REFERENCE_STEP_0001.npz` и `REFERENCE_NEWTON_0001.json` для принятого шага.
NPZ содержит механические коэффициенты, электрические коэффициенты при ВКЛ,
остаток и обобщённые реакции `constraint_reaction` (нормальная к допустимым
вариациям часть внутреннего остатка минус заданные нагрузки). В отчёте есть
максимальный срединный прогиб `w_middle_abs_max_m`. Неуспешная итерация
записывается как `REFERENCE_FAILED_ITERATE.npz` и не считается принятым шагом.
Формат этих файлов отличается от старых STEP-файлов; старый постпроцессор
нельзя применять без адаптера.

Ограничения: до 256 поверхностных узлов; по умолчанию до 256 свободных степеней
свободы (жёсткий максимум 512). Минимальная квадратура по толщине: 3 точки
для KL/FSDT/TE1, 5 для TE2, 7 для Reddy/TE3, 9 для TE4. Это предотвращает
явное недоинтегрирование и не заменяет проверку квадратурной/сеточной
сходимости. Разреженная сборка и Ньюмарк остаются следующими этапами;
проверочный полный цикл МВИ описан ниже. Проверки нового решателя — `tests/test_variational_fdm.py`, включая
реальный связанный расчёт CUF TE1, сохранение полей, седловую электрическую
систему и отказ при вырожденной касательной.


## Полный статический цикл МВИ с G3D и флексо

`numerics/cylinder_variational_mvi.py` выполняет чередование X/Y для всех
механических и электрических коэффициентов того же функционала. В каждом
полушаге фиксируется семейство-партнёр, а связанная система Ньютона решается
только по активным профилям с учётом механических, высших и электрических ГУ.
Общий с МКР код Ньютона используется для решения в выбранном подпространстве;
полносеточная поправка равновесия не выполняется.

Запуск проверочного примера:

```bash
python RUN_FINAL_CASE.py config/CASE_REFERENCE_CUF_G3D_MVI_STATIC.json
```

Отличия CASE: `method="MVI"`, `rank=1..8`, `mvi_grid` вместо `fdm_grid`,
`reference_mvi.max_sweeps`. Параметры полушагов Ньютона остаются в
`reference_newton`. Ранг не должен превышать ни nx, ни ns. Для серии всех
восьми рангов нужна сетка не меньше 8×8; для CUF TE1 с приведёнными ГУ это
также требует увеличить `reference_newton.max_free_dofs` до 512. Это всё ещё
плотный проверочный маршрут. Ранг больше размера сетки явно отклоняется.

Представление сохраняется как
`u = state_scales * (lift_scaled + einsum("crx,crs->cxs", X, Y))`.
Здесь c перечисляет сначала механические, затем электрические коэффициенты.
`lift_scaled` накладывает заданные граничные значения; разложение описывает
добавку к этому поднятию. QR меняет координаты профилей с сохранением поля и
дополняет неактивные семейства, чтобы нулевые поля не блокировали следующий
полушаг. При продолжении по нагрузке начальное поле должно представляться
выбранным рангом; физически значимые компоненты не отбрасываются ради ранга.

После полного цикла повторно вычисляются остатки обоих семейств и полный
допустимый узловой остаток. `converged=true` требует полного равновесия;
малый проекционный остаток при большом полном получает статус
`PROJECTED_ONLY_FULL_RESIDUAL_NOT_CONVERGED`. Это не принятый шаг. Автоматического
повышения ранга, подмены МВИ на МКР или продолжения нагрузки после такого шага нет.
Реакции выделяются относительно полного пространства допустимых вариаций,
а не относительно подпространства одного полушага.

В NPZ дополнительно сохраняются `x_profiles`, `y_profiles`, `lift_scaled`,
`state_scales`. Журнал `REFERENCE_MVI_0001.json` содержит полушаги и контроль
полных циклов; summary — ранг, число циклов, проекционный и полный остатки.
`run_mvi_rank_series`/`RUN_MVI_1_8.py` проверяет все запрошенные ранги до создания
результатов, затем запускает их независимо и сохраняет отдельные статусы.
Неуспех одного ранга не скрывает результаты следующих.

Проверки `tests/test_variational_mvi.py`: активация рангов 1–8 с нуля,
электрическая седловая система, недостаточность ранга, ненулевые ГУ,
продолжение по нагрузке, вырожденная касательная, сохранение профилей и
сравнение настоящего связанного CUF TE1/G3D/флексо с МКР на одинаковой сетке.
Приём CASE проверяется для KL, FSDT, Reddy и CUF TE1–TE4 с флексо ВКЛ/ВЫКЛ;
это не означает завершённую физическую верификацию всех теорий и рангов.

### Динамика Ньюмарка с МВИ/МКР

`numerics/cylinder_variational_dynamic.py` подключает Ньюмарк к тому же
связанному функционалу и вариационным ГУ. На каждом времени механическое
ускорение вычисляется из эффективной кинематики Ньюмарка, после чего полный
цикл МВИ либо МКР решает совместные механические и электрические уравнения.
Потенциал остаётся квазистатическим и не получает электрической массы.
Пример: `config/CASE_REFERENCE_CUF_G3D_MVI_DYNAMIC.json`.

Поддерживаются FSDT, Reddy и CUF TE1–TE4. Для нелинейной KL пока нужен точный
зависящий от конфигурации оператор директорной инерции с гироскопическими
членами, поэтому динамический KL явно отклоняется. Начальное состояние сейчас
ZERO и должно быть в равновесии в `start_time_s`; нагрузку можно задержать либо
начать гармоникой с нулевой фазой. Предварительно нагруженное начальное
состояние ещё не подключено.

`dynamics.time_law` принимает постоянную, ступенчатую, линейно нарастающую,
гармоническую, затухающую, многочастотную, частотный свип, прямоугольный,
полусинусный, треугольный, гауссов и табличный законы. Проверяется разрешение
частоты/импульса шагом времени. Механические и электрические естественные ГУ
могут иметь собственные временные законы. Для заданного перемещения или
потенциала временной закон пока отклоняется: нужны явные совместимые скорость
и ускорение заданного следа.

На каждом принятом шаге сохраняются `mechanical`, `electrical`, `velocity`,
`acceleration`, полный эффективный остаток и реакции. Для МВИ также сохраняются
X/Y-профили. `REFERENCE_DYNAMIC_HISTORY.csv` содержит краткий временной ряд,
а `FINAL_RUN_SUMMARY.json` — статус каждого шага. Непрошедший полный остаток
останавливает расчёт и не считается принятым временем.

Проверка одного физического шага CUF TE1/G3D/флексо дала совпадение МВИ-1 и
МКР до 1.8e-25 по механическим коэффициентам и 4.5e-25 по потенциалу на сетке
4×4. Это программная проверка одинаковых уравнений, а не исследование
сходимости по сетке, рангу и шагу времени.


## Окно проверочного вариационного CASE

Вкладка файлов содержит кнопку «Новый CASE: G3D / флексо / МВИ…».
«Загрузить CASE» открывает проверочный CASE в этом же редакторе без переноса
в обычные поля, для которых действуют другие единицы, сетки и настройки.
Выбираются теория, CUF TE1–TE4, МВИ/МКР, ранг 1–8, сетка, квадратура,
материал, G3D и явный переключатель флексоэффекта ВКЛ/ВЫКЛ. В отдельных
JSON-полях доступны полный паспорт механических, высших и электрических ГУ,
нагрузка/шаги и параметры Ньютона. Редактор сохраняет неизвестные ему
дополнительные поля CASE без перезаписи обычным форматом GUI.

При ФЛЕКСО ВЫКЛ физические μ₁, μ₂, κ равны нулю; электропотенциал и
электрические ГУ исключаются. Редактор хранит прежние введённые значения и
электроды только как данные интерфейса для повторного включения. Он проверяет
настройки решателем до сохранения. Кнопки «Рассчитать» и «МВИ 1–8» сначала
сохраняют проверенный CASE, затем запускают его через обычный журнал и
управление процессом GUI. Для МВИ 1–8 все ранги проходят предварительную
проверку сетки до создания результатов; нужна сетка не меньше 8×8 и лимит
свободных степеней для этой теории. Старый постпроцессор STEP для формата
REFERENCE_STEP пока не подходит; результаты смотрят по NPZ и summary.

Проверка отображения данных редактора без оконного сервера:
`tests/test_reference_gui.py`. Динамика в проверочном маршруте по-прежнему
отклоняется до подключения полного шага Ньюмарка.
