# Выбор метода интегрирования по времени в GUI

В главном окне и редакторе вариационного CASE добавлен **общий**
переключатель:

- **Ньюмарк** — основной режим, используется по умолчанию;
- **Гаусс–Рунге–Кутта IRK4 (эксперимент)** — только динамический МВИ,
  самостоятельный решатель, сохраняющий фиксированный ранг.

Переключатель задаёт **маршрут расчёта**, а не физическое свойство
оболочки. Сохранённый CASE не дополняется новым ключом интегратора.
Теория, материал, градиентная модель, граничные условия, сетка, ранг,
временной закон и плотность не изменяются при выборе метода.

Кнопка «Рассчитать» в главном окне или редакторе использует
`plan_time_integrator_run` и `execute_time_integrator_plan`.
Физический CASE проверяется до запуска, а перед исполнением
проверяется, что его содержимое не поменялось после проверки.

Для IRK4 каталог вычисляется из каталога Ньюмарка с суффиксом
`_GAUSS2_IRK4`, например `OUTPUT_DYNAMIC_GAUSS2_IRK4`.
Совпадение результатов двух методов исключено. Непустой каталог
не перезаписывается. Кнопка «МВИ 1–8» остаётся доступной только
с Ньюмарком. Статические задачи и МКР не переключаются на МВИ+IRK4.

**Ограничения экспериментального IRK4 остаются:** малые сетки,
неподвижные механические опоры, конечное поле должно укладываться в
фиксированный ранг. Никакой скрытой смены ранга и метода при
неудачном шаге не происходит. Численные эксперименты для всех семи
кинематик и подтверждение порядка по времени пока не завершены.

Регрессионные тесты: `tests/test_time_integrator_gui.py`.
Полный запуск оболочки при добавлении переключателя не выполнялся.
