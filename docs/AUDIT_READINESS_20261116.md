## Воспроизведённые и исправленные дефекты

1. **Масштаб невязки energy-FDM.** Виртуальная работа содержит площадь
   ячейки, а прежний масштаб невязки переносился из strong-FDM как плотность.
   В алгебраической проверке при нагрузке 100 Па и масштабе 10 000 Па
   уменьшение размеров в 1000 раз давало норму `3.7699e-9 < 1e-8` на нулевом
   поле. Теперь масштабы механических и электрических уравнений умножаются
   на те же площадные веса до проекции. При масштабах размеров 1, 1e-3,
   1e-6 безразмерная невязка тестовой нагрузки остаётся 0.01. Искусственная
   линейная задача с малой геометрией требует ненулевой поправки Ньютона.
   Физический функционал, нагрузка и допуск не изменены.
2. **Переполнение/обнуление проекции масштабов.** Нормы считаются после
   нормировки; проверены положительные масштабы 1e-200 и 1e200.
3. **Электрическая совместимость.** Прямой API energy-FDM теперь проверяет
   суммарный заряд с учётом заданного торцевого электрического потока перед
   статикой, инициализацией и каждой временной стадией. Устранение координаты
   калибровки не может скрыть несовместимый источник. CASE-маршрут имел
   дополнительную проверку через общий preflight; закрыт и прямой API.
4. **Падающий тест торца.** Для кубического поля дискретная `D_x` слева
   равна `-2 dx²`, а внешняя нормальная производная — `+2 dx²`.
   Исправлены два ошибочных ожидания и пояснение в журнале. Оператор не менялся.
5. **Папка результатов в нативном GUI.** Выбор существующего родителя
   формирует новый, ещё не созданный подкаталог. Ранее выбранная папка
   неизбежно отклонялась runner-ом как уже существующая.
6. **Смена постановки во время работы.** Заблокирована смена CASE и папки
   активного процесса, чтобы график и команда остановки не меняли адресата.
7. **Ложные 100% прогресса.** `STEP_0000` больше не считается выполненным
   физическим шагом даже при одном запрошенном шаге.
8. **Завершение и остановка.** Читатель stdout дожидается exit code.
   Остановка имеет terminate/kill и сохраняет `STOPPED_BY_USER` после выхода
   worker-а. Закрытие окна дожидается остановки и записи статуса.
9. **Переносимость energy-FDM результатов.** Папка содержит исходные NPZ,
   переносимый CASE, оригинальный CASE и INPUT_MANIFEST с SHA-256 входов,
   Git SHA и признаком изменённых исходников. Сохраняются именно сырые
   электрические источники, чтобы повторное чтение не удвоило поверхностный
   заряд. Установка из ZIP без Git явно остаётся без подтверждённой SHA.

## Границы готовности

Для самостоятельных исследовательских запусков energy-FDM выбирается явно:
`INDEPENDENT_ENERGY_FDM_COUPLED_RESEARCH_V1`. Старый strong CASE продолжает
запускать strong-FDM; автоматической подмены метода нет. Открыть CASE можно
через меню «Нативные МКР/МВИ — связанный G3D/Gz CASE» в основном интерфейсе.
Для разбора результата нужна вся папка с CASE, INPUT_MANIFEST, NPZ и
RUN_SUMMARY, а не только график.

**Не объявлено исправленным или физически подтверждённым:**

- В старом strong-FDM остаётся установленное несовпадение осевых операторов
  и граничной работы; energy-FDM — отдельная согласованная дискретная ветка.
- Длительная нелинейная динамика новой energy-FDM, сеточная/временная
  сходимость и сопоставление FDM–МВИ-1–8 на одной исправленной SHA ещё
  требуют физических запусков пользователя.
- Полнота высших механических и электрических условий на реальных
  поверхностях не доказана одной проверкой дискретной вариации.
- Текущий связанный CASE поддерживает `IMMOBILE_PARALLEL_ENDS`, постоянные
  FDM-источники и до 120 временных шагов. Произвольные свободные/заделанные
  торцы и меняющаяся во времени FDM-нагрузка этим интерфейсом не заявляются.

Успех программных тестов не заменяет указанные физические проверки.
